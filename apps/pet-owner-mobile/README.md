# Vetalya pet-owner app

Runnable Expo Router application for Android and iOS using the same Spring Boot `/api` as the React/Vite web portal. Shared transport lives in `packages/api-client`; owner API contracts and validation live in `packages/owner-domain`.

Includes email/password sign-in and registration, secure refresh storage, Home, pets, passport, available-slot booking, visit cancellation, signed records and prescriptions, vaccination care, profile editing and persistent hospital-sharing access with revocation. Staff accounts use the web hospital portal.

## Run locally

Use a supported Node release for Expo SDK 58. From this directory:

```sh
npm ci
cp .env.example .env
npm start
```

Set `EXPO_PUBLIC_API_BASE_URL` to the shared backend, including `/api`. Android emulator: `http://10.0.2.2:8080/api`; iOS simulator: `http://localhost:8080/api`. Physical devices require a reachable LAN address or HTTPS endpoint. Production requires HTTPS. Never place secrets in public Expo variables.

Use `npm run android` / `npm run ios` with the relevant emulator/simulator installed. A development build is recommended for secure storage, custom schemes and future provider integration: configure EAS and use the existing development profile in `eas.json`. Native platform projects are generated by Expo; they are not committed here.

## Verify

```sh
npm run typecheck
npm run lint
npx expo export --platform all
```

Both native bundles were exported locally. Store binaries, signing, physical-device testing and store submission remain release work. Set registered `APP_IDENTIFIER`, `APP_SCHEME`, `APP_VARIANT` and matching backend callback configuration before creating distributable builds.

Google/Apple native sign-in, account recovery, push delivery, private file upload, atomic rescheduling, pharmacy, payments and service marketplace integrations remain pending. The UI marks unsupported services explicitly. Signed clinical records are read-only; owner passport details are separate caregiver information.
