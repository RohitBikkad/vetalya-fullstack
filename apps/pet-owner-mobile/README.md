# Vetalya pet-owner app

Runnable Expo Router application for Android and iOS using the same Spring Boot `/api` as the React/Vite web portal. Shared transport lives in `packages/api-client`; owner API contracts and validation live in `packages/owner-domain`.

Includes email/password sign-in, required email OTP verification for registration, Android Google sign-in, secure refresh storage, Home, pets, passport, available-slot booking, visit cancellation, signed records and prescriptions, vaccination care, profile editing and persistent hospital-sharing access with revocation. Staff accounts use the web hospital portal.

## Run locally

Use a supported Node release for Expo SDK 58. From this directory:

```sh
npm ci
cp .env.example .env
npm start
```

Set `EXPO_PUBLIC_API_BASE_URL` to the shared backend, including `/api`. Android emulator: `http://10.0.2.2:8080/api`; iOS simulator: `http://localhost:8080/api`. Physical devices require a reachable LAN address or HTTPS endpoint. Production requires HTTPS. Never place secrets in public Expo variables.

Use `npm run android` / `npm run ios` with the relevant emulator/simulator installed. A native development or staging build is required for Google sign-in; Expo Go does not include its native module: configure EAS and use the existing development profile in `eas.json`. Native platform projects are generated by Expo; they are not committed here.

## Verify

```sh
npm run typecheck
npm run lint
npx expo export --platform all
```

Both native bundles were exported locally. Store binaries, signing, physical-device testing and store submission remain release work. Set registered `APP_IDENTIFIER`, `APP_SCHEME`, `APP_VARIANT` and matching backend callback configuration before creating distributable builds.

Apple/iOS Google sign-in, account recovery, push delivery, private file upload, atomic rescheduling, pharmacy, payments and service marketplace integrations remain pending. The UI marks unsupported services explicitly. Signed clinical records are read-only; owner passport details are separate caregiver information.

See [shared backend setup](../../docs/SHARED_WEB_ANDROID_IOS_SETUP.md) and [redesign release notes](../../docs/PET_OWNER_REDESIGN_RELEASE.md).


## Android Google and verified email

The `staging` EAS profile supplies the shared HTTPS API and `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`. Register the staging Android package and EAS SHA-1 in the same Google Cloud project as the web client. The native SDK exchanges a Google ID token for the backend’s normal owner session. Google client secrets and mail credentials stay off the device.

For email/password registration, send an email code, verify it, then create the account with the one-use email verification receipt. No code is returned by the send API. Mail delivery failures are shown rather than simulated. SMTP settings belong to Spring Boot on Render; staging supports the main service’s Brevo relay on port 2525 using required STARTTLS.

See [Google and email setup](../../docs/GOOGLE_AND_EMAIL_VERIFICATION.md) for environment variables, certificate details and server verification behavior. iOS is deferred for this authentication update. Builds and API checks do not replace testing Google account selection on a physical Android device.
